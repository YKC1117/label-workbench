Canonical semantics: Box x/y/width/height describe stroke centerline rectangle; expected ink includes half the stroke on each side. Line x/y is unrotated start of local path, width/height its endpoint vector; the adapter uses endpoint setters and explicitly checks the resulting Center anchor/absolute angle, rather than misusing X/Y as top-left. Only upright primitive models are enabled in this candidate. Images currently require embedded monochrome non-interlaced 8-bit PNG, measured 300x300dpi driver, and an independent declared-image pattern check. Resampling has a one-driver-dot bound (2 export pixels at 600dpi), measured from real Windows PrinterSettings; this is independent of unchanged .5mm physical geometry gates. Missing/other driver resolution fails closed. Run47's source mask vs native raster shows edge dither at up to this bound; wrong image content is rejected. Original text/barcode optical tolerances are unchanged.

Visible HRI is a restricted native Arial12/center profile with explicit canonical gap1.1mm and caption-frame height. Other typography/gaps/rotation remain blocked. Actual stable bar band and caption ink are segmented from native bitmap and compared separately: symbol footprint/bar height, caption center/top/containment, effective HRI value, Save/reopen font/visibility/value and strict challenge coupling. No free width/height stretching.

A hollow border can legally enclose text. Its full per-object white interior is not a comparable transparency constraint. Registration therefore requires every actual border ink pixel, globally unique; an independent hollow/stroke/edge-content gate rejects filled or malformed borders. Duplicate/missing patterns remain unresolved. Quiet-zone checks use border stroke ink rather than a falsely filled AABB. New regressions cover these positive and negative cases. No gate tolerance has been raised to accept misplacement.

Remaining: native paragraph/fixed Text justification, color/JPEG/interlaced/indexed images, rotated primitives and arbitrary native HRI styling are not enabled. New mixed candidate runtime must pass before any new capability is reported as verified.

## Run48 real mixed candidate: hot native/editability PASS, visual comparison FAIL

Run 41605935058 / 7ac2d33fa731811b76935202d2d5b1b237929f30. All seven native objects were created with correct types, saved/reopened, and passed payload or stroke/image edit challenge + exact restore and strict peer checks (including actual Picture peer bitmap SHA). Source image geometry readbacks also passed; Windows PrinterSettings independently reports Argox CP-3140 PPLA 300x300dpi. No property/source contamination failure occurred. Cold phase NOT RUN because visual comparison failed, and original candidate was quarantined.

Original exact tile registration was unresolved for TITLE14, line, logo and HRI even though all were visible in the whole-page actual BMP. Border and non-caption barcodes already uniquely registered. Two distinct native rasterization phases can have a printer-dot edge/dither difference at the same physical position. The comparator now keeps exact matching first, and only for the new profile permits global bidirectional native ink registration within ONE independently measured printer dot (2 export pixels at 600dpi/300dpi). It never restricts search to the expected coordinates. Candidate translations must recover the SAME exact measured page ink bounding box; more than one distinct bounding box remains ambiguity and fails. Negative regressions retain duplicate patterns and damaged/missing ink rejection. Original .5mm physical geometry gates are unchanged. HRI bar/caption bounds are now measured from the registered whole-page ROI, not inferred from per-object bounds.

Image comparison required a separate comparability correction. A nearest-neighbor ideal pixel is not a resampled/dithered native edge pixel. Original one-dot ideal-image test failed 21 edge pixels; area reconstruction differed in four source boundary cells, while all 5776 source interior cells reconstructed EXACTLY. The blocking content gate now compares exact binary interiors whose 3x3 source neighborhood is constant. Filter-support boundary cells are DIAGNOSTIC_ONLY; their counts remain reported. To prevent this hiding thin/damaged content, every source cell must be within one source cell of a same-color interior core (morphological support), and native raster must retain >=2 output pixels per source cell. Thin/unsupported features fail closed rather than being ignored. Wrong/mirrored images, interior content damage, filled boxes and malformed lines are rejected by independent tests. Source data SHA, visible image edit/restore, physical ink extent, global unique registration, and mandatory source-hidden cold-process exact BMP proof are additional independent gates. No translation, crop compensation, warp or greater physical tolerance is applied.

Reanalysis of unchanged Run48 evidence under the corrected comparability policy is recorded separately as offline PASS; Run48 remains FAIL and has no cold proof. A new combined runtime must validate the full pipeline.
